# 문항 원본 형식 (`data/math/problems.src.json`)

이 문서는 관리자가 고치는 문항 원본 파일 `data/math/problems.src.json`의 형식을 설명합니다.
이 파일은 배열(`[ … ]`)이며, 문항 하나가 객체 하나입니다. 배포용 파일 `site/data/math/problems.json`은 `tools/build_problems.py`가 이 원본으로부터 자동 생성하므로 직접 고치지 않습니다.

원본을 고치고 `main`에 올리면 GitHub Actions(`.github/workflows/build-problems.yml`)가 배포용 파일을 다시 만듭니다. 수식 변환이나 출처 문구 계산은 모두 이 단계에서 일어나며, 사용자 브라우저는 그 결과를 이어 붙이기만 합니다.

## 필드 한눈에 보기

| 필드 | 형식 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | 문자열 | 예 | 문항 고유 번호. 중복되지 않게 씁니다. 예: `edu-2022-09-g1-q21` |
| `src` | 객체 | 예 | 출처 정보. `org` 값에 따라 쓰는 키가 다릅니다 (아래 참고) |
| `subject` | 문자열 | 예 | 과목명. 예: `공통수학2`. 중학교 개념만으로 풀리는 문항은 `중학교` (unit: `대수`·`함수`·`기하`·`확률과 통계`) |
| `unit` | 문자열 | 예 | 단원명. 예: `도형의 방정식` |
| `points` | 숫자 | 예 | 예상 배점. 소수 한 자리까지 쓸 수 있으며, 시험지에 `[3.5점]`처럼 표시되고 정렬에도 쓰입니다 |
| `rate` | 숫자 또는 `null` | 예 | 정답률(%). 정답률 필터와 자동 정렬에 쓰입니다. 모르면 `null` |
| `type` | 문자열 | 예 | 문항 유형. `선택형` 또는 `단답형`. 정답 표시(①~⑤)는 `선택형`일 때만, `단답형`은 `answer` 값을 그대로 씁니다 |
| `answer` | 정수 | 예 | 정답 번호. 선택지 순서(1부터 시작)의 번호입니다. 예: 3이면 셋째 선택지 |
| `area` | 문자열 | 예 | 교과. 지금은 `"math"` |
| `standards` | 문자열 배열 | 예 | 2022 개정 성취기준 코드, 핵심 코드를 맨 앞에 (분석 팀 기준 자료 `analysis-team/reference/`) |
| `outOfCurriculum` | 참/거짓 | 아니요 | 2022 개정 교육과정 밖 개념이 필요하면 `true` |
| `concepts` | 문자열 배열 | 예 | 핵심 개념 태그. 예: `["원의 평행이동", "점과 직선 사이의 거리"]` |
| `stem` | 문자열 | 예* | 발문. 수식은 `$…$`, 밑줄은 `<u>…</u>`로 감쌉니다. *`image`를 쓰면 생략 가능 |
| `choices` | 문자열 배열 | 예* | 선택지 문자열 목록. 보통 5개. *`image`를 쓰면 생략 가능 |
| `figure` | 문자열 | 아니요 | 발문 아래에 넣을 그림 파일 경로 (`data/math/` 기준). 예: `images/edu-2022-09-g1-q21-fig.png` |
| `figureWidthMm` | 숫자 | 아니요 | 그림의 가로 폭(mm). 생략하면 40mm |
| `image` | 문자열 | 아니요 | 문항 전체를 그림 한 장으로 넣을 때의 파일 경로. 지정하면 발문·선택지 텍스트 대신 이 그림이 쓰입니다 |

빌드 스크립트는 위 필드 중 `id`, `subject`, `unit`, `points`, `rate`, `type`, `answer`, `concepts`를 값 그대로 옮깁니다. 값의 범위나 형식을 검사하지는 않으므로, 입력할 때 아래 규칙을 직접 지켜 주세요.

## `src` (출처)

출처 문구는 `src` 필드에서만 만듭니다. 문항 안에 출처를 직접 쓰지 않습니다. 문구를 만드는 함수는 `tools/build_problems.py`의 `format_source()` 하나입니다.

`org`는 다음 세 가지 중 하나입니다.

**`edu`: 시·도교육청 전국연합학력평가**

| 키 | 예 | 설명 |
| --- | --- | --- |
| `org` | `"edu"` | |
| `year` | `2022` | 시행 연도 |
| `grade` | `"고1"` | 학년 |
| `month` | `9` | 시행 월 |
| `subject` | `"공통수학2"` (선택) | 과목. 있을 때만 문구에 들어갑니다 |
| `no` | `21` | 문항 번호 |

생성되는 출처 문구:
- `{"org":"edu","year":2022,"grade":"고1","month":9,"no":21}` → `2022년 고1 9월 전국연합학력평가 21번`
- 같은 값에 `"subject":"공통수학2"`를 더하면 → `2022년 고1 9월 전국연합학력평가 공통수학2 21번`

**`kice`: 한국교육과정평가원 (모의평가·수능)**

| 키 | 예 | 설명 |
| --- | --- | --- |
| `org` | `"kice"` | |
| `year` | `2025` | 학년도 |
| `month` | `6` | 시행 월. **11이면 수능**, 그 밖의 월은 모의평가 |
| `subject` | `"미적분"` (선택) | 과목 |
| `no` | `30` | 문항 번호 |

생성되는 출처 문구:
- `{"org":"kice","year":2025,"month":6,"subject":"미적분","no":30}` → `2025학년도 6월 모의평가 미적분 30번`
- `{"org":"kice","year":2026,"month":11,"no":22}` → `2026학년도 대학수학능력시험 22번`

학교 시험(내신) 문항은 받지 않습니다. 배점(예: 3.5점)과 출제 체계가 수능·모의평가·학력평가와 달라 검색 기준이 흐트러지기 때문입니다. `org` 가 `edu`·`kice` 가 아니면 빌드가 멈춥니다.

## `stem`, `choices` (발문과 선택지)

- 수식은 `$…$`로 감쌉니다. 안의 내용은 LaTeX 문법을 따릅니다. 예: `$x^2+y^2=4$`, `$\left(\frac{1}{2},\,0\right)$`
- JSON 문자열 안에서는 역슬래시를 두 번 씁니다. 예: `"$\\{1\\}\\subset A$"`, `"$(3,\\,4)$"`
- 밑줄은 `<u>…</u>`로 감쌉니다. 예: `"다음 중 <u>틀린</u> 설명을 고르면?"`
- `choices`의 각 항목도 같은 규칙을 따릅니다. 선택지 번호(①~⑤)는 자동으로 붙으므로 쓰지 않습니다.
- 빌드는 선택지가 모두 한 칸에 들어가면 3열 표 배치, 아니면 한 줄씩 배치로 정합니다. 이 판단도 자동입니다.

### 지원하지 않는 LaTeX 명령은 일부러 빌드를 멈춥니다

한글 수식 변환기가 모르는 명령은 빌드 단계에서 오류로 멈춥니다. 시험지에 잘못된 수식이 나가는 것을 막기 위해서입니다. 오류가 나면 해당 명령을 지원되는 형태로 고치세요.

- 예: `\varnothing`은 오류가 납니다. 대신 `\emptyset`을 쓰세요.
- 지원 여부가 애매하면 로컬에서 `python3 tools/build_problems.py data/math/problems.src.json <임시 경로>`를 먼저 돌려 확인하세요.

## `figure`, `image` (그림)

- 경로는 원본 파일이 있는 `data/math/` 기준입니다. 파일은 `data/math/images/` 아래에 두는 것이 관례입니다.
- 빌드는 그림 파일의 가로·세로 크기를 읽어 시험지 배치에 씁니다. 파일이 없으면 빌드가 실패합니다.
- `figure`는 발문 아래에 들어가는 그림입니다. 발문과 선택지 텍스트는 그대로 나갑니다.
- `image`는 문항 전체를 그림 한 장으로 바꿉니다. 이 경우 시험지에는 그림만 들어가며 `stem`과 `choices`는 쓰이지 않습니다. 텍스트로 옮기기 어려운 문항에만 씁니다.
- 빌드는 쓰인 그림을 `data/math/`에서 `site/data/math/`로 복사합니다.

## 정렬

시험지의 문항 순서는 사용자가 담은(끌어서 바꾼) 순서 그대로입니다. '자동 정렬' 버튼이나 '결과 모두 선택'을 쓰면 `points`가 작은 순서, 같으면 `rate`가 큰 순서로 정렬하며(`sortProblems()`), `rate`가 `null`이면 같은 배점 안에서 가장 뒤로 갑니다.

## 전체 예시 한 개

형식을 보여 주기 위한 예시입니다(실제 기출이 아닙니다). 그림·밑줄·선택지 표기가 모두 들어 있습니다.

```json
{
  "id": "edu-2000-03-g1-q12",
  "area": "math",
  "src": {"org": "edu", "year": 2000, "grade": "고1", "month": 3, "no": 12},
  "subject": "공통수학2",
  "unit": "도형의 방정식",
  "standards": ["<성취기준 코드>"],
  "points": 3,
  "rate": null,
  "type": "선택형",
  "answer": 3,
  "concepts": ["원과 직선의 위치 관계"],
  "stem": "그림은 원 $x^2+y^2=1$이다. 이 원과 직선 $y=x$의 위치 관계로 <u>옳은</u> 것은?",
  "figure": "images/edu-2000-03-g1-q12-fig.png",
  "figureWidthMm": 25,
  "choices": [
    "만나지 않는다",
    "한 점에서 만난다",
    "서로 다른 두 점에서 만난다",
    "$x$축 위의 한 점에서만 만난다",
    "원의 중심을 지나지 않는다"
  ]
}
```

이 예시를 빌드하면 `source`는 `2000년 고1 3월 전국연합학력평가 12번`이 되고, `answer` 3은 셋째 선택지를 가리킵니다.
테스트용 예시 문항은 `test/fixtures/`에 따로 있으며 사이트에는 나오지 않습니다.

## 입력 전 확인할 것

1. `id`가 다른 문항과 겹치지 않는지 확인합니다.
2. `answer`가 선택지 개수 안의 번호인지 확인합니다 (보통 1~5).
3. `src`의 `org`에 맞는 키를 모두 넣었는지 확인합니다.
4. 수식의 역슬래시를 `\\`로 적었는지, 지원하지 않는 명령을 쓰지 않았는지 확인합니다.
5. `figure`나 `image`에 적은 파일이 `data/math/` 아래에 실제로 있는지 확인합니다.
6. 로컬에서 `npm run build`로 빌드가 통과하는지 확인합니다. 결과물은 `site/data/`에 쓰이므로, 확인만 하려면 빌드 결과를 커밋하지 마세요.
